## Places where the brief and CLAUDE.md contradict themselves

1. The brief approves "RuboCop with the Rails defaults". Rails 8.1 ships `rubocop-rails-omakase` for that, so that gem is what I install.
2. The brief says containers run read-only "wherever possible". Rails writes to `tmp/` and `log/`. Those two get a tmpfs mount, and the rest of the filesystem stays read-only.
3. The brief asks for a test "against real MySQL" and also for "handler tests with mocked database". Both exist. They are different tiers, named `*.test.ts` and `*.integration.test.ts`.
4. The global CLAUDE.md asks for snake_case file names and makes React apps the exception. So `apps/handlers` and `packages/shared` use snake_case, and `apps/web` uses camelCase with PascalCase components.
5. The global `devsecops-pipeline` skill asks for self-hosted runners, Traefik, cosign and SBOMs. This repository's CLAUDE.md asks for GitHub Actions, host nginx and gitleaks. The repository wins, per rule 13.

## Rails concepts this phase introduces

- **`rails new`**: the generator that writes the whole application skeleton. The closest thing in Node is `nest new`. The exact command and what it skipped go in the learning guide.
- **The Gemfile and `Gemfile.lock`**: the same job as `package.json` and the lockfile. Bundler is the package manager.
- **`config/database.yml`**: one file that holds the database settings for development, test and production. It is YAML run through ERB, so `<%= ENV["X"] %>` reads an environment variable.
- **Environments**: Rails picks `development`, `test` or `production` from `RAILS_ENV`, and loads `config/environments/<name>.rb`.
- **`bin/rails`**: the entry point for every command. It is a Ruby script, which is why line endings matter.
